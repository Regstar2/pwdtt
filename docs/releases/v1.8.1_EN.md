# PWDTT v1.8.1

[Русская версия](v1.8.1.md)

PWDTT v1.8.1 fixes Windows VK authentication through Microsoft Edge when the browser login succeeds but PWDTT does not receive a completed session.

## Highlights

- Fixed the false `Microsoft Edge завершился до открытия VK` failure.
- PWDTT no longer treats termination of the Edge launcher process as termination of the whole browser authentication flow.
- Once Chrome DevTools Protocol is attached, auth-session liveness is determined from the actual CDP/WebSocket connection instead of the PID of the process that launched Edge.
- The fix applies both to interactive VK login and to the browser fallback used to obtain a VK Calls access token.
- Added regression coverage for Edge process handoff.

## User-visible behavior

On Windows, the expected flow is again:

1. open **VK hashes**;
2. select **Sign in to VK**;
3. finish authentication in Microsoft Edge;
4. wait until PWDTT reports **VK: Authorized**;
5. create VK call hashes normally.

Manual VK hash entry is unchanged.

## Installation and update

Recommended Windows package:

`pwdtt-windows-amd64-setup.exe`

Portable Windows package:

`pwdtt-windows-amd64.exe`

The release also provides:

- `pwdtt-linux-amd64`;
- `PWDTT-macos.zip`;
- `SHA256SUMS`.

Updating from v1.8.0 requires no profile or settings migration. The code change is limited to the Windows VK browser-auth flow, plus release documentation.

Rollback is possible by manually reinstalling v1.8.0. A dedicated rollback smoke test was not performed for this patch release.

## Security

- VK access tokens and cookies are not exposed to React or release diagnostics;
- local VK state continues to use Windows DPAPI;
- the Windows release pipeline supports Authenticode when a signing certificate is configured;
- if no certificate is configured, the workflow records the unsigned fallback explicitly;
- `SHA256SUMS` is published for the final payload files.

## Limitations

- automatic VK authentication and hash generation are Windows-only;
- Microsoft Edge is required for browser authentication;
- the feature depends on the external VK OAuth/API flow and may require further changes if VK changes its behavior;
- Authenticode status of the published Windows artifacts depends on the release workflow result.

## Compatibility

Profile format, manual VK hash entry, tunnel behavior, WireGuard flow, and server protocol are unchanged.
