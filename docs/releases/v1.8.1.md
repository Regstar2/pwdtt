# PWDTT v1.8.1

[English version](v1.8.1_EN.md)

PWDTT v1.8.1 исправляет Windows-авторизацию VK через Microsoft Edge, которая могла не завершаться в приложении после успешного входа в браузере.

## Главное

- Исправлен ложный сбой `Microsoft Edge завершился до открытия VK`.
- PWDTT больше не считает завершение launcher-процесса Edge завершением всего browser auth flow.
- После подключения к Chrome DevTools Protocol состояние авторизации определяется по фактическому CDP/WebSocket-сеансу, а не по PID исходного процесса Edge.
- Исправление применяется как к интерактивному входу VK, так и к browser fallback при получении VK Calls access token.
- Добавлены regression-тесты на передачу окна между процессами Edge.

## Для пользователя

На Windows сценарий снова должен работать так:

1. открыть раздел **VK-хеши**;
2. нажать **Войти в VK**;
3. завершить вход в открывшемся Microsoft Edge;
4. дождаться состояния **VK: Авторизован** в PWDTT;
5. создавать VK call hashes как обычно.

Ручной ввод VK-хешей не изменён.

## Установка и обновление

Для Windows рекомендуется:

`pwdtt-windows-amd64-setup.exe`

Portable-вариант:

`pwdtt-windows-amd64.exe`

Также публикуются:

- `pwdtt-linux-amd64`;
- `PWDTT-macos.zip`;
- `SHA256SUMS`.

Обновление с v1.8.0 не требует миграции профилей или настроек. Изменения затрагивают только Windows VK browser-auth flow и документацию.

Откат возможен ручной установкой v1.8.0. Отдельный rollback smoke для этого patch-релиза не выполнялся.

## Безопасность

- access token и cookies VK не передаются в React и не добавляются в release diagnostics;
- локальное состояние VK продолжает храниться через Windows DPAPI;
- Windows release pipeline поддерживает Authenticode при настроенном сертификате;
- если сертификат отсутствует, pipeline явно фиксирует unsigned fallback;
- для финальных payload-файлов публикуется `SHA256SUMS`.

## Ограничения

- автоматическая авторизация и генерация VK-хешей доступны только на Windows;
- для browser auth требуется Microsoft Edge;
- работа зависит от внешнего VK OAuth/API flow и может потребовать новых изменений при изменении поведения VK;
- наличие Authenticode-подписи конкретных Windows-артефактов определяется результатом release workflow.

## Совместимость

Формат профилей, ручной ввод VK-хешей, туннель, WireGuard flow и серверный протокол не менялись.
