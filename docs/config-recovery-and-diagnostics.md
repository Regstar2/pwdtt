# Восстановление конфигурации и приватность диагностики

## Что происходит при повреждении JSON

При запуске приложение проверяет `config.json` и JSON-файлы серверных профилей. Отсутствующий `config.json` — нормальная ситуация при первом запуске, поэтому используются настройки по умолчанию без предупреждения.

Если файл существует, но JSON повреждён или не соответствует ожидаемой структуре, приложение **сначала перемещает оригинал** в том же каталоге в файл вида `<имя>.json.corrupt-<UTC>-<UUID>.bak`. Байт-содержимое резервной копии остаётся неизменным. Затем:

- для `config.json` применяются настройки по умолчанию; они будут записаны при следующем изменении настроек;
- повреждённый профиль не включается в список серверов, но его оригинал сохранён в `servers/` как `.bak`;
- при запуске показывается уведомление, а журнал содержит сообщение `[RECOVERY]` без полного пути и персональных имён.

Каталог настроек:

- Windows: `%APPDATA%\pwdtt\`;
- Linux: обычно `~/.config/pwdtt/` (либо каталог `os.UserConfigDir()`);
- macOS: каталог `os.UserConfigDir()/pwdtt/`.

### Как восстановить данные вручную

1. Закройте PWDTT.
2. Найдите файл `.corrupt-*.bak` рядом с исходным `config.json` или в папке `servers`.
3. Скопируйте его **в другое безопасное место**, затем проверьте и исправьте JSON в текстовом редакторе. Не удаляйте `.bak`.
4. Переименуйте исправленную копию в исходное имя `.json` и запустите приложение.
5. Если формат не удаётся исправить, создайте профиль заново. Резервная копия остаётся доступной для ручного извлечения реквизитов.

Если файл нельзя прочитать либо переместить в карантин (например, из-за прав доступа), PWDTT сообщает об ошибке и **блокирует перезапись** файла. Для устранения нужно исправить права или вручную сохранить копию и освободить исходный путь. Восстановление не пытается обходить ошибки доступа.

**Важно:** резервные копии серверных профилей могут содержать пароли, VK-хеши и идентификаторы. Не публикуйте их и не прикладывайте к issue. Новые файлы, записываемые приложением, создаются с ограниченными разрешениями (в пределах возможностей ОС).

## Экспорт Bug Report

По умолчанию отчёт содержит ОС и архитектуру, версию Go и PWDTT, описание прав доступа, ограниченные UI-события и журнал выбранной сессии. Hostname и абсолютный каталог конфигурации в заголовке отчёта не публикуются.

Сообщения санитизируются при попадании в UI/журнал и повторно при экспорте. Маскируются полные URL (включая обычные и URL-encoded VK join ссылки), известные токены, идентификаторы, пользовательские имена и типовые локальные пути. Значения неизвестных URL query-параметров также скрываются. Отчёт сохраняет технические этапы и коды ошибок для диагностики.

Автоматическое редактирование текста не гарантирует обнаружения всех возможных секретов из произвольных новых форматов логов. **Перед публикацией всё равно просмотрите скопированный отчёт вручную.**

## Автоматические проверки

- `go test ./backend ./core/...` — восстановление отсутствующих, повреждённых и нечитаемых JSON, конкурентная загрузка, redaction.
- `cd frontend && npm test -- --run` — санитизация до хранения UI-события и регрессии логов.
