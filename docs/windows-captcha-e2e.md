# Windows: проверка CAPTCHA VK (issue #43)

Автоматические тесты работают без реальных VK-токенов. Для подтверждения браузерного пути нужен отдельный ручной E2E на Windows с действительной CAPTCHA VK.

## Автоматические проверки

Из корня репозитория:

```powershell
go test -count=1 ./backend
Push-Location .\core
go test -race -count=1 ./...
Pop-Location
Push-Location .\frontend
npm ci
npm test
npm run lint
npm run build
Pop-Location
```

Windows тесты `vk_captcha_windows_test.go` проверяют URL allowlist и разбор ответов официального `captchaNotRobot.check`. Фикстуры `core/testdata/captcha_v2_*.html` синтетические и **не являются** сохранённым приватным HTML VK. Новый неподтверждённый формат `window.init` намеренно не угадывается.

## Ручной E2E (Windows + Microsoft Edge)

1. Запустить PWDTT из ветки PR с включённым диагностическим режимом. Подключиться к серверу, для которого VK действительно требует CAPTCHA.
2. Проверить, что ошибка парсинга `window.init` показывает только `phase`, `category`, `reason`, HTTP status, content type, redirect flag, bytes и duration. Секретный URL, HTML, session token и success token **не должны** появляться в логах или экспорте.
3. При нераспознанной странице Go v2 не должен повторять заведомо такой же запрос. В главном окне появляется ручной этап с обратным отсчётом.
4. Нажать **«Открыть CAPTCHA VK»**. В Edge должна открыться **официальная** страница VK. Выполнить CAPTCHA собственными действиями, без автоматизации прохождения. После ответа VK `status=ok` приложение должно автоматически получить `success_token`, закрыть Edge и продолжить запрос VK-кредов.
5. Повторить подключение и нажать **«Отменить CAPTCHA»**: ожидание завершается, последующий токен не принимается. В следующем подключении прежний ответ не должен разблокировать новую CAPTCHA.
6. Повторить и нажать **«Отключиться»** во время открытого Edge. Проверить немедленную отмену ожидания, закрытие управляемого окна и отсутствие продолжения подключения.
7. Проверить сценарии недоступности страницы, отклонённой CAPTCHA, истечения времени и закрытого вручную Edge. UI должен показывать понятную ошибку и не зависать.

## Ограничения

- Windows manual flow работает через управляемый Microsoft Edge; на других ОС этот путь не реализован.
- CDP распознаёт только подтверждённый текущим кодом VK ответ `captchaNotRobot.check` со `status=ok` и `success_token`. Если VK изменит endpoint/схему или запретит диагностический доступ браузера, автоматическое извлечение токена может перестать работать. Это блокер для принятия ручного E2E, а не причина подделывать или обходить CAPTCHA.
- Время ручного шага не больше 60 секунд и дополнительно ограничено родительским дедлайном VK credentials (90 секунд). UI показывает фактический дедлайн.
- По умолчанию не требуется и не следует собирать либо прикладывать приватный HTML VK к issue. Для анализа достаточно безопасных метаданных и воспроизводимого сценария.

PR можно сливать только после успешных CI и реального Windows E2E.
